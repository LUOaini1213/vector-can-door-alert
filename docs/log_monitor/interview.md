# 项目讲法与追问

当前可以说：

> 我最近在 AI 辅助下补了车辆日志分析学习项目，把自己项目生成的 CAN 仿真日志解析入 DuckDB，按教学规则检查信号无效、速度突变和报文超时。看板可以从异常追踪到源 ASC 行号和恢复帧。我正在通过手写 SQL、调整参数和补边界测试，逐步独立掌握这条链路。

实际演示可以打开 MON01，指出 0.2 秒的速度变化，再选择跨分钟超时，展示 1.1 秒锚点与 61.1 秒恢复。自动验收数量、来源和运行证据见冻结报告；不要把仿真日志说成实车采集，也不要把已有代码说成已经独立完成。

常见追问：

- **监控事件与 warning 有什么区别？** warning 是原控制器写进 0x200 的输出；监控事件由分析规则生成，两者分别存储和展示。
- **超时为什么不是 300 ms 那一刻？** 规则允许帧龄等于 300 ms，微秒精度下首次超过阈值是 300,001 μs。原控制器按 10 ms 周期评估，因此最早可观察的输出时点不同。
- **没有恢复帧怎么办？** 截止到日志末尾，标为尚未观察到恢复，不向未来补时长。
- **一分钟超时为什么能大于 60 秒？** 两个 ID 或多个通道的异常区间会叠加，是累计信号时长，不能当成整车停机时长。
- **重复帧怎么处理？** 原始重复保留；相同日志内容与模型指纹重跑跳过导入。这两种“重复”含义不同。
- **怎样证明不只是在看界面？** 从空白写事件分组查询，再用 LEFT JOIN 连接原始帧；现场改一个阈值，预测并验证变化。

当你亲手做过后，再补充“我独立修改了哪条规则、增加了哪项测试、定位了什么问题”。每一句个人贡献都对应实际操作和文件差异。
